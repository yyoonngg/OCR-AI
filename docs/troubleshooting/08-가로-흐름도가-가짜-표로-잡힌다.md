# 가로로 늘어선 흐름도 라벨이 표로 잡힌다

- 날짜: 2026-08-17
- 대상: `backend/app/layout.py` — `analyze_page`
- 상태: 완화 (한 행짜리는 본문으로 되돌림)

## 증상

암호화 흐름도가 있는 교재 페이지에서 한 행짜리 "표"가 여러 개 나왔다.

```
[표 1x6] 평문 | 암호화 | 5%6+828 8-822 | -58/-1 암호문 | 복호화 | 노향진서
[표 1x3] / | 6100435436109672526059215447241 10 암호화 키 | ...
[표 1x6] 평문 | 암호화 | 8%8+828 8abh 8^822 | 822 458/-10 암호문 | 복호화 | ...
```

원본은 `평문 → 암호화 → 암호문 → 복호화 → 평문` 형태의 도표다.

## 원인

두 가지가 겹쳤다.

1. **좌표만 보면 가로로 늘어선 도표 라벨과 표의 한 행은 구분되지 않는다.**
   둘 다 "같은 y에 x가 떨어진 셀 여러 개"다.
2. `_table_runs`는 밴드 2개 이상을 요구하지만,
   [05](05-세로가운데정렬-라벨에서-행이-어긋난다.md)의 이어지는 줄 병합을 거치고 나면
   **행이 1개로 쪼그라들 수 있다.** 판정 시점과 최종 행 수가 달라진 것이다.

## 해결

표를 다 만든 **뒤에** 검사해서, 행이나 열이 2개 미만이면 본문 블록으로 되돌린다.

```python
table = _make_table(...)
if table.rows >= 2 and table.columns >= 2:
    blocks.append(table)
else:
    blocks.append(_make_text(...))
```

판정을 구성 전이 아니라 구성 후로 옮긴 것이 핵심이다.

## 검증

해당 페이지의 가짜 표 3개가 사라졌다.

```
before: 표=['2x2', '1x6', '1x3', '1x6']
after:  표=['2x2']
```

다른 입력의 표 개수는 변하지 않았다.

## 남은 것

**2행 이상인 도표는 여전히 표로 잡힌다.** 위 페이지에 남은 `2×2`가 그 경우로,
`키`와 긴 숫자열이 두 줄로 배치된 도표다. 좌표만으로는 갈라낼 수 없다.

이건 레이아웃 분석 모델(PP-Structure 등)이 필요한 영역이다.
지금 구조에서는 `analyze_page()`만 갈아끼우면 되고 응답 스키마는 그대로 쓸 수 있다.
