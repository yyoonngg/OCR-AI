# 세로 가운데 정렬된 항목 이름 때문에 행이 어긋난다

- 날짜: 2026-08-17
- 대상: `backend/app/layout.py` — `_rows_of`
- 상태: 해결 (첫 열 앵커 + 가까운 행에 붙이기)

## 증상

[04](04-줄바꿈된-셀에서-표가-끊긴다.md)를 고친 뒤, **낮은 해상도 크롭에서는 완벽한데
전체 페이지 해상도에서는 행이 밀렸다.**

```
| 구분   | 개념
|        | 오직 인가된 사람 ... 시스템에 접근    ← 첫 칸이 비어 있다
| 기밀성(Confidentiality) | 해야 한다는 원칙   ← 이름이 두 번째 줄과 짝지어졌다
| 가용성(Availability) | 원에 접근하여사용할수있는성질 정당한 사용자가 ...
                          ↑ 순서까지 뒤집혔다
```

## 원인

항목 이름이 **세로 가운데 정렬**이라, 셀 내용이 두 줄일 때 이름은 첫 줄이 아니라
가운데 줄과 겹친다.

```
기밀성 행의 실제 좌표 (1224px 렌더 기준)

  "오직 인가된 사람 ..."   y 310~327    ← 이름과 안 겹침
  "기밀성(Confidentiality)" y 330~348
  "해야 한다는 원칙"        y 338~355    ← 이름과 겹침
```

밴드 묶기(세로 겹침 기준)를 하면 첫 줄이 혼자 밴드가 되고, 이름은 두 번째 줄과
같은 밴드가 된다. 밴드를 그대로 행으로 쓰면 위와 같이 밀린다.

해상도가 낮은 크롭에서는 줄 높이 대비 겹침이 커서 셋이 한 밴드로 묶였고,
그래서 우연히 맞았던 것이다. **저해상도에서 통과했다고 안심하면 안 된다.**

## 해결 — 첫 열을 차지하는 밴드만 행으로 본다

1. **앵커**: 첫 열에 줄이 있는 밴드 = 실제 행
2. 나머지 밴드는 **세로로 더 가까운 앵커에 붙인다** (위·아래 양쪽 대응)
3. 셀 안에서는 y 순으로 정렬해 원래 문장 순서를 복구

```python
nearest = min(anchors, key=lambda a: _gap_between(band, bands[a]))
```

`오직 인가된...`은 위(머리글 행)와의 간격보다 아래(기밀성 행)와의 간격이 작아서
기밀성 행에 붙는다. 반대로 아래로 넘어간 줄은 위 행에 붙는다.

### 한 줄이 둘로 쪼개진 경우

검출기가 한 줄을 좌우 두 박스로 쪼개는 경우가 있다. y로만 정렬하면 오른쪽 조각이
먼저 나올 수 있어서, **y 차이가 줄 높이의 70% 안이면 같은 줄로 보고 x 순으로 읽는다.**

```python
tolerance = max(_line_height(group) * 0.7, 1.0)
group.sort(key=lambda l: (int(l.bbox.y / tolerance), l.bbox.x))
```

이걸 넣기 전에는 부인방지 행이
`증 명하여 나중에 ... 행위나 이벤트의 발생 을`로 뒤집혀 나왔다.

## 검증

전체 페이지 해상도(1224px)와 크롭 모두에서 `7×2`, 모든 셀 내용·순서 정상.
교재 3쪽 접근통제 표도 불릿 3줄짜리 셀이 올바른 순서로 합쳐진다.

## 남은 것

- 첫 열(항목 이름) 자체가 줄바꿈되면 앵커가 두 개 생겨 별도 행이 된다
