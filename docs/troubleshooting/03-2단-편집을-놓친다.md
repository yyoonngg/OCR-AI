# 2단 편집을 놓치고 좌우가 섞인다

- 날짜: 2026-08-17
- 대상: `backend/app/layout.py` — `_column_layout`, `_gutter_positions`
- 상태: 해결 (XY-cut + 구분선 분리)

## 증상

2단 편집 문서에서 `page_columns: 1`이 나오고, 읽는 순서가 좌우로 번갈아 섞였다.

```
1. 추진 배경
2. 기대 효과          ← 오른쪽 단이 여기 끼어든다
현재 문서 처리 업무는 대부분
OCR 도입 시 입력 시간이
수작업으로 이루어지고 있다.
건당 4분에서 30초로 줄어든다.
```

게다가 좌우 문단이 `2×2 표`로 오인됐다.

## 원인

단을 나누려면 "어떤 줄도 가로지르지 않는 세로 여백"을 찾아야 하는데,
**가운데 정렬된 제목 한 줄이 단 사이를 가로지른다.**

```
        업무 자동화 도입 계획          ← 이 줄 하나가 x 430~810을 덮는다
  ─────────────────────────────
  1. 추진 배경        2. 기대 효과
  현재 문서 처리...    OCR 도입 시...
                ↑
        여백이 여기 있지만 제목에 막힌다
```

제목 하나 때문에 페이지 전체에서 완전히 빈 x 구간이 없어진다.

## 시도 — 가로부터 자르기 (부분적으로만 성공)

XY-cut으로 세로가 안 되면 가로로 자르고 각 조각에서 다시 세로를 시도하게 했다.
제목은 분리됐지만, **본문 사이 빈 줄에서도 가로 절단이 일어나 단이 조각났다.**
조각이 작아지면 "단마다 줄 3개 이상" 조건에 걸려 다시 실패하고,
남은 좌우 짝이 `2×2 표`가 됐다.

## 해결 — 가로지르는 줄을 구분선으로 뺀다

여백을 찾을 때 **가로지르는 줄을 일정 비율까지 허용**한다 (`MAX_GUTTER_CROSSING = 0.08`).
그 줄들은 본문이 아니라 **구분선**으로 보고 따로 빼서, 그 위아래로 단을 나눠 읽는다.

```python
spanning = [line for line in lines if crosses(line)]   # 가운데 정렬 제목 등
rest     = [line for line in lines if not crosses(line)]
# 구분선의 y를 경계로 위아래를 나누고, 각 구간에서 왼쪽 단부터 읽는다
```

우연히 걸친 짧은 줄이 구분선이 되지 않도록 **영역 너비의 20% 이상**인 줄만 인정한다
(`MIN_SPANNING_WIDTH`).

## 검증

```
page_columns: 2, 표 오인식 0개

[단0] 업무 자동화 도입 계획      ← 구분선
[단0] 1. 추진 배경
[단0] 현재 문서 처리 업무는 대부분 / 수작업으로 ... / 월 평균 ...
[단0] 오류율은 2.7% 수준으로 / 재작업 비용이 매년 증가한다.
[단1] 2. 기대 효과
[단1] OCR 도입 시 입력 시간이 / 건당 4분에서 ... / 연간 절감 ...
[단1] 정확도는 98% 이상을 목표로 / 단계적으로 검증한다.
```

거래명세서 샘플은 `page_columns: 1` 그대로 유지됐다 (회귀 없음).

## 남은 것

- **단 밖의 꼬리말**: 왼쪽 아래 꼬리말은 왼쪽 단의 끝으로 읽힌다.
  구분선이 아니라 왼쪽 단에 속한 것으로 판정되기 때문
- 3단 이상도 구조상 되지만 검증하지 않았다
