# 줄바꿈된 셀이 있으면 표가 거기서 끊긴다

- 날짜: 2026-08-17
- 대상: `backend/app/layout.py` — `_table_runs`, `_try_add`
- 상태: 해결 (셀 개수 → 열 구조 유지 여부)
- 제보: 실제 교재 페이지 테스트 (`기초강의.pdf` 1쪽)

## 증상

6행짜리 표가 **2행으로 쪼그라들었다.** 기밀성·무결성·가용성 행과 머리글이
표에서 빠져 본문 블록으로 떨어져 나갔다.

```
[본문]  구분 개념
[본문]  기밀성(Confidentiality) 오직 인가된 사람 ...
[표 2x2]
   | 인증성(Authentication)   | 임의 정보에 접근할 수 있는 ...
   | 책임추적성(Accountability) | 보안 목적에는 개체의 행동을 ...
[본문]  부인방지(Non-repudiation) 행위나 이벤트의 발생을 ...
```

## 원인

표 구간을 **"셀 개수가 같은 연속된 행"** 으로 잡고 있었다.
그런데 셀 내용이 두 줄로 넘어가는 행은 줄 수가 하나 더 많다.

```
구분   | 개념                                   ← 2줄
기밀성 | 오직 인가된 사람 ... 시스템에 접근      ← 3줄 (셀이 줄바꿈)
       | 해야 한다는 원칙
무결성 | 정보의 내용이 ...                      ← 2줄
가용성 | 정당한 사용자가 ... 객체 또는 자        ← 3줄
       | 원에 접근하여 사용할 수 있는 성질
인증성 | 임의 정보에 ...                        ← 2줄
```

`[2, 3, 2, 3, 2, 2, 2]`가 되어 같은 값이 연속되는 구간만 표로 잡혔다.
그게 마지막 `[2, 2, 2]` 중 일부였다.

## 해결 — 열 구조가 유지되는가로 판단

행을 하나씩 얹으면서 **열 구조가 깨지는 순간**에만 표를 끊는다.

한 열에 여러 줄이 배정됐을 때:

- **가로로 겹치면** → 줄바꿈된 같은 셀 (계속 진행)
- **가로로 떨어져 있으면** → 새로운 열이 생긴 것 (표가 바뀜, 끊는다)

```python
for previous, current in zip(group, group[1:]):
    if previous.bbox.x + previous.bbox.width <= current.bbox.x:
        return None   # 겹치지 않는다 = 구조가 바뀌었다
```

이 규칙이 거래명세서에서 품목 표(4열)와 항목-값 표(2열)를 정확히 갈라 준다.
품목 행의 `수량`·`단가`·`금액`은 이전 표의 값 열 하나에 몰려 들어가는데,
서로 가로로 떨어져 있으므로 거기서 표가 바뀐 것으로 판정된다.

## 검증

```
[표 7x2 header=True]
  | 구분                       | 개념
  | 기밀성(Confidentiality)    | 오직 인가된 사람 ... 접근 해야 한다는 원칙
  | 무결성(Integrity)          | 정보의 내용이 ...
  | 가용성(Availability)       | 정당한 사용자가 ...
  | 인증성(Authentication)     | 임의 정보에 ...
  | 책임추적성(Accountability)  | 보안 목적에는 ...
  | 부인방지(Non-repudiation)  | 행위나 이벤트의 발생을 ...
```

교재 3쪽 접근통제 표(불릿 2~3줄짜리 셀)도 `4×2`로 정상.
거래명세서 샘플은 `5×2` + `4×4` + `3×2` 유지.

## 남은 것

- **첫 열 자체가 줄바꿈되면** 별도 행이 된다.
  이어지는 줄 판정이 "첫 열이 아닌 열"을 기준으로 하기 때문
- 세로 병합 셀(rowspan)은 여전히 표를 끊는다
