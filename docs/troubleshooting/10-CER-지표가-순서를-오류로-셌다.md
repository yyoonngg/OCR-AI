# CER 지표가 검출 순서 변화를 인식 오류로 셌다

- 날짜: 2026-08-17
- 대상: 저품질 입력 벤치마크 (측정 코드)
- 상태: 해결
- 성격: **측정이 틀려서 결론이 정반대로 나올 뻔한 사례**

## 증상

열화 조건별 OCR 성능을 문자 오류율(CER)로 재는 벤치마크를 만들었더니,
**기울기(skew)가 압도적으로 최악**으로 나왔다.

```
조건            줄    평균신뢰도     CER
기울기 3°       39     0.984    14.0%
기울기 8°       39     0.985    34.2%
```

이대로면 "제일 먼저 고칠 건 기울기 보정(deskew)"이 결론이다.

## 이상한 점

**신뢰도가 0.985로 원본과 똑같았다.** 인식이 34% 틀렸는데 모델이 그걸 모른다?
다른 조건에서는 CER이 오르면 신뢰도가 같이 떨어졌다.

```
흐림 r=2.0     0.801 → CER 31.6%   (신뢰도 같이 떨어짐, 일관적)
기울기 8°      0.985 → CER 34.2%   (신뢰도 그대로, 이상함)
```

## 원인

CER을 이렇게 계산하고 있었다.

```python
text = "\n".join(l.text for l in res.lines)   # 검출 순서 그대로
```

`res.lines`는 **검출 순서**다. 이미지를 회전하면 검출기가 줄을 훑는 순서가 바뀐다.
내용이 하나도 안 틀려도 순서만 다르면 편집 거리가 크게 나온다.

좌표로 정렬해서 다시 재봤지만 CER은 13.3%로 거의 그대로였다. 회전하면 y 좌표가
밀려서 정렬 버킷 경계를 넘나들기 때문이다. **지표를 고쳤다고 생각했는데 안 고쳐졌다.**

## 확인 — 숫자 말고 출력을 봐야 했다

원본과 기울기 3°의 줄 목록을 diff로 직접 찍었다.

```
+한국디지털전환 주식회사
-한국디지털전환 주식회사
+홍길동 책임 · hong.gildong@example.co.kr · 010-2345-6789
-홍길동 책임 · hong.gildong@example.co.kr · 010-2345-6789
+금액
-금액
```

**모든 `+`에 내용이 완전히 같은 `-`가 짝지어져 있다.** 오인식은 0건이고 순서만 다르다.

## 해결 — 순서와 무관한 줄 매칭

줄 단위로 최적 매칭한 뒤 짝지어진 줄끼리만 CER을 계산한다.

```python
def line_metrics(ref, hyp):
    remaining = list(hyp)
    for r in ref:
        best = 가장 유사한 hyp 줄 (SequenceMatcher.ratio)
        if 유사도 >= 0.5:
            remaining.remove(best); total += cer(r, best)
        else:
            missing += 1; total += 1.0   # 아예 못 찾은 줄
```

## 결과 — 결론이 뒤집혔다

| 조건 | 잘못된 지표 | 올바른 지표 |
| --- | --- | --- |
| 기울기 3° | 14.0% | **0.0%** |
| 기울기 8° | 34.2% | **0.0%** |
| 흐림 r=2.0 | 30.9% | 31.6% |
| 축소 40% | 21.8% | 22.7% |

**기울기는 문제가 아니었다.** RapidOCR의 검출이 기울어진 텍스트를 다각형으로 잡고
perspective 크롭으로 펴기 때문에 8°까지도 무손실이다. deskew 전처리를 붙였다면
아무 효과 없는 코드를 넣고 "왜 안 나아지지" 하고 있었을 것이다.

진짜 변수는 **글자 크기와 선명도**였다. (→ [11번 문서](11-저품질-입력은-전처리로-못-고친다.md))

## 배운 것

- **지표가 측정하려는 걸 측정하는지 먼저 검증하라.** CER은 순서에 민감한데
  OCR 검출 순서는 입력에 따라 바뀐다. 둘을 섞으면 노이즈를 신호로 읽는다.
- **다른 지표와 어긋나면 그게 단서다.** "CER은 34%인데 신뢰도는 그대로"가
  이상하다는 신호였는데, 처음엔 그냥 "모델이 자기 오류를 모르나 보다"로 넘겼다.
- **숫자가 이상하면 원본 출력을 봐라.** diff 한 번으로 5분 만에 끝날 일이었다.
