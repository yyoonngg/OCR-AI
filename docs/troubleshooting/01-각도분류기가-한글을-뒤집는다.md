# 각도 분류기가 정상 한글 줄을 180도 뒤집는다

- 날짜: 2026-08-16
- 대상: `backend/app/ocr.py`
- 상태: 해결 (기본값 off + UI 토글)

## 증상

거래명세서 샘플에서 일부 줄이 알아볼 수 없는 문자열로 나왔다.

```
0.613  FY IY  H H          ← "거래명세서"
0.738  (%OL)|Y∠            ← "부가세(10%)"
```

동시에 검출된 줄 수가 실제보다 적었다(39줄 중 35줄). `발행일자`, `담당자`,
`결제조건` 줄이 통째로 사라졌다.

## 원인

`(%OL)|Y∠`를 뒤집어 보면 `(10%)`다. RapidOCR 기본값으로 켜져 있는 각도 분류기
`ch_ppocr_mobile_v2.0_cls`가 **똑바로 놓인 한글 줄을 180도 뒤집힌 것으로 오판**하고 있었다.
이 모델은 중국어 기준으로 학습돼서 한글 자소 구조에 맞지 않는다.

뒤집힌 줄은 인식 신뢰도가 떨어지고, `Global.text_score`(기본 0.5) 필터에 걸려
아예 결과에서 빠지기도 한다. 사라진 줄들이 이 경우였다.

## 확인 방법

`text_score`를 0.05로 낮춰서 필터를 사실상 끄면, 사라진 줄이 저신뢰 쓰레기 문자열로
살아난다. 여기서 "검출은 됐는데 인식이 깨진 것"임을 알 수 있었다.

```
0.349 y=1008 거어ㄷ해라|어큰      ← "위와 같이 거래 내역을 확인합니다."
```

## 해결

각도 분류기를 기본으로 끈다. RapidOCR 3.x는 호출 단위로 끌 수 있다.

```python
result = engine(array, use_cls=use_angle_cls)   # 기본 False
```

지우지 않고 `use_angle_cls` 파라미터와 화면 우상단 "회전 보정" 체크박스로 남겨 뒀다.
뒤집힌 스캔을 실제로 다뤄야 할 때는 필요하다.

## 검증

| | 켰을 때 | 껐을 때 |
| --- | --- | --- |
| 검출 줄 수 | 35 | **39** |
| 신뢰도 0.9 미만 | 2줄 | **0줄** |
| 소요 시간 | 2.73s | **2.51s** |
| `거래명세서` | `FY IY H H` | `거래명세서` |
| `부가세(10%)` | `(%OL)\|Y∠` | `부가세(10%)` |

끄는 쪽이 정확도·속도 모두 낫다.

## 남은 것

- 실제로 뒤집혀 들어온 스캔은 여전히 수동으로 토글해야 한다
- 한국어에 맞는 각도 분류 모델이 있으면 기본으로 켜는 게 맞다
