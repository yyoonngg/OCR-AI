# 인식은 맞는데 띄어쓰기가 사라진다

- 날짜: 2026-08-16
- 대상: `backend/app/spacing.py`
- 상태: 해결 (원본 픽셀 잉크 투영)

## 증상

글자는 정확한데 공백이 자주 빠진다.

```
·결제조건:세금계산서발행일로부터30일이내 현금 지급
·납품장소: 서울특별시 강남구 테헤란로152,8층
2026년8월 16일
```

원본 이미지에는 공백이 분명히 있다. PP-OCR 인식 모델이 흘린 것이다.

## 시도 1 — 한국어 띄어쓰기 교정기 (Kiwi) ❌

`kiwipiepy 0.23.2`의 `kiwi.space(lines, reset_whitespace=False)`를 붙여 봤다.
목표한 줄은 잘 고쳤지만 **문서에 없던 공백까지 넣어 복합명사를 다 쪼갰다.**

```
거래명세서         -> 거래 명세서
문서번호           -> 문서 번호
공급가액           -> 공급 가액
부가세(10%)        -> 부가세(10 %)
(주)에이엑스솔루션  -> (주)에이 엑스 솔루션
한국디지털전환      -> 한국 디지털 전환
```

39줄에 1052ms까지 걸렸다. **문서 OCR에서 원하는 건 "문법적으로 옳은 띄어쓰기"가 아니라
"원본에 있던 공백"** 이라는 게 여기서 분명해졌다. 의존성을 제거했다.

## 시도 2 — CTC 문자 박스의 간격 ❌

RapidOCR의 `return_single_char_box=True`로 글자별 좌표를 받아 간격을 재려 했다.
그런데 이 좌표는 CTC 프레임 인덱스에서 역산한 것이라 **약 5px 단위로 뭉개져 있다.**

```
'지'  l=589 r=608
'급'  l=613 r=633   gap=0.17   ← "지급" 안쪽인데
'이'  l=502 r=519
'내'  l=519 r=536   gap=0.00
'현'  l=546 r=565   gap=0.34   ← 실제 공백
'지'  l=589 r=608   gap=0.17   ← 실제 공백인데 위 "급"과 같은 값
```

같은 0.17이 실제 공백이기도 하고 글자 사이이기도 하다. 임계값을 어디에 둬도
재현율이 절반을 못 넘었다.

## 해결 — 원본 픽셀을 직접 본다

언어 모델도, 인식 모델이 준 좌표도 아니고, **원본 이미지의 실제 여백**을 잰다.

1. 검출된 줄 다각형을 똑바로 편 크롭으로 만든다 (기울어진 스캔 대응, `warpPerspective`)
2. Otsu 이진화 후 열 방향 잉크 투영으로 획이 하나도 없는 열 구간을 찾는다
3. 그중 **폭이 중앙값의 2배 이상**인 구간만 단어 사이 공백으로 인정한다
   (`max(중앙값 * 2, 줄높이 * 0.18)`)
4. 글자 박스와 대조해 몇 번째 글자 앞인지 정하고 공백을 넣는다

인식 결과에 이미 있는 공백은 건드리지 않고 없는 자리에만 추가한다.

### 자간 넓힌 제목 예외

`거 래 명 세 서`처럼 자간을 벌린 제목은 모든 글자가 떨어져 있다. 그대로 두면
전부 공백이 들어간다. **검출된 공백 수가 글자 수와 같으면 단어 구분이 아니라고 보고
건너뛴다.**

### 안전장치

글자 박스 개수와 공백 제외 글자 수가 맞지 않으면 대응을 신뢰할 수 없으므로
원본을 그대로 돌려준다.

## 검증

샘플 39줄 중 8줄 복원, **전부 원본 문구와 정확히 일치**, 오삽입 0건.

```
2026년8월 16일               -> 2026년 8월 16일
문서 OCR 엔진라이선스(연간)   -> 문서 OCR 엔진 라이선스 (연간)
·결제조건:세금계산서발행일로부터30일이내 현금 지급
  -> · 결제조건: 세금계산서 발행일로부터 30일 이내 현금 지급
·납품장소: 서울특별시 강남구 테헤란로152,8층
  -> · 납품장소: 서울특별시 강남구 테헤란로 152, 8층
```

건드리지 않은 것: `거래명세서`, `문서번호`, `공급가액`, `합계금액`, `부가세(10%)`.
글꼴 크기·노이즈를 섞은 별도 테스트에서도 오삽입 0건.

비용은 39줄에 **6~20ms**. `return_single_char_box`를 켠 데 따른 인식 속도 저하는
측정되지 않았다 (2617ms → 2597ms).

## 남은 것

- **원본에도 공백이 없으면 복원할 게 없다.** `띄어쓰기가전혀없는문장`은 그대로 남는다.
  이건 문법 기반 교정 영역이라 LLM 후처리 대상
- 글자가 붙어 인쇄된 저해상도 스캔은 잉크 투영이 뭉개져 효과가 떨어진다
- 세로쓰기는 대상이 아니다
