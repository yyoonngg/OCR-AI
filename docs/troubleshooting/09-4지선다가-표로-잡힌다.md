# 4지선다 선택지가 표로 잡힌다

- 날짜: 2026-08-17
- 대상: `backend/app/layout.py` — `_is_choice_list`
- 상태: 해결 (항목 번호 마커로 판별)
- 제보: 사용자 직접 테스트

## 증상

문제 아래 4지선다 선택지가 `표 4×3`으로 잡혔다.

```
[표 4x3]
  | 무결성 | (나) 가용성 | (다) 기밀성 |
  | 무결성 | 기밀성      | 가용성      |
  | 기밀성 | 가용성      | 무결성      |
  | 기밀성 | 무결성      | 가용성      |
```

## 원인

**좌표만 보면 이건 완전한 격자다.** 잘못 잡은 게 아니라, 표와 구분할 정보가
기하에 없다.

```
    (가)      (나)      (다)
① 무결성    가용성    기밀성
② 무결성    기밀성    가용성
③ 기밀성    가용성    무결성
④ 기밀성    무결성    가용성
```

머리줄이 있고, 행마다 셀이 같은 열에 정렬돼 있다. 폭 비율, 행 간격, 셀 길이 —
어느 것도 진짜 표와 갈리지 않았다.

## 해결 — 첫 열의 항목 번호

기하가 아니라 **내용**에 신호가 있다. 첫 열에 `①②③④` 같은 항목 번호가 붙어 있다.
실제 표의 첫 열에는 이런 게 없다.

| 블록 | 첫 열 | 마커 |
| --- | --- | --- |
| 정보보호 목표 표 | 구분 / 기밀성(Confidentiality) / ... | 없음 |
| 품목 표 | 품목 / 문서 OCR 엔진 라이선스 / ... | 없음 |
| 접근통제 표 | 단계 / 식별 / 인증 / 인가 | 없음 |
| 합계 표 | 공급가액 / 부가세(10%) / 합계금액 | 없음 |
| **4지선다** | **① 무결성 / ② 무결성 / ③ 기밀성 / ④ 기밀성** | **있음** |

```python
_LIST_MARKER = re.compile(r"^(?:[①-⑳㉑-㊿㈀-㈞]|\(?\d{1,2}[.)]|[가-힣][.)])\s*\S")
```

두 가지를 조심했다.

- **첫 행 예외**: `(가) (나) (다)` 라벨 줄에는 번호가 없다.
  그래서 "2개 이상 일치 + 첫 행을 뺀 나머지가 모두 일치"로 판정한다.
- **번호만 있는 칸은 제외**: 마커 뒤에 내용이 이어져야 한다(`\s*\S`).
  `번호 | 항목 | 금액` 표의 `1`, `2`, `3` 열은 목록 마커가 아니다.

판정되면 표 대신 본문 블록으로 내보낸다. 격자 배치는 줄바꿈으로 살아 있다.

## 2차 — 마커가 검출되지 않는다

여기까지 하고 "해결"이라고 했는데, 제보자 환경에서는 여전히 표로 나왔다.
제보 화면의 표를 다시 보니 셀에 `①②③④`가 **아예 없었다.**

```
| 무결성 | (나) 가용성 | (다) 기밀성 |     ← ① 이 없다
```

`①`은 글자가 작아서 검출을 놓치는 경우가 있다. 내 테스트 이미지에서는 둘 다
`① 무결성`으로 붙어 나왔기 때문에 통과했던 것이다. **한 렌더에서 됐다고 끝난 게 아니다.**

마커 위치를 흰색으로 덮은 이미지를 만들어 재현했다.

```python
for y in (694, 722, 752, 783):
    draw.rectangle([40, y-4, 68, y+26], fill=(255,255,255))
```

→ `표 5×3`, 마커 없음. 제보와 동일.

### 보조 신호

마커가 없어도 4지선다는 이렇게 생겼다.

1. **바로 앞 블록에 물음표로 끝나는 문장이 있다** (문제)
2. 칸이 전부 짧다 (≤ 12자)
3. **같은 값이 자리만 바꿔 반복된다** — 15칸에 6종류

3번이 핵심이다. 실제 표는 칸마다 값이 달라 반복률이 낮다.

| 블록 | 칸 수 | 서로 다른 값 | 비율 |
| --- | --- | --- | --- |
| 4지선다 | 15 | 6 | **0.40** |
| 품목 표 | 16 | 13 | 0.81 |

임계값은 0.6.

### 뺀 조건

처음에는 "숫자 칸이 없을 것"도 넣었는데 **바로 그것 때문에 안 걸렸다.**
`(나)`가 `(4)`로 오인식되면서 숫자 칸으로 판정됐기 때문이다.
답이 숫자인 문제도 흔하니 이 조건은 제거했다.

## 검증

```
[본문]
  (가) (나) (다)
  ① 무결성 가용성 기밀성
  ② 무결성 기밀성 가용성
  ③ 기밀성 가용성 무결성
  ④ 기밀성 무결성 가용성
```

마커가 있는 경우(고·저해상도 크롭)와 **마커를 지운 경우** 모두 본문으로 나온다.

```
opt_hi.png       표=['7x2']                 마커 있음
opt_lo.png       표=['7x2']                 마커 있음(저해상도)
opt_nomark.png   표=['7x2']                 마커 지움 ← 제보 재현
sample.png       표=['5x2', '4x4', '3x2']   변화 없음
page2.png        표=['4x2']                 변화 없음
```

테스트 4개 추가.

- `test_numbered_choices_are_not_a_table` — 마커 있는 선택지
- `test_choices_without_markers_are_not_a_table` — 마커 없는 선택지
- `test_short_table_after_question_stays_a_table` — 값이 다르면 문제 뒤라도 표
- `test_plain_number_column_stays_a_table` — `1`,`2`,`3` 번호 열은 마커가 아니다

## 배운 것

**기하로 안 되는 것도 있다.** 지금까지는 내용 기반 신호(글자 길이)를 버리고
기하로 옮기는 게 대체로 옳았지만([07](07-표가-2단으로-오인된다.md)),
여기서는 반대였다. 격자 배치가 동일하면 좌표에는 답이 없다.

## 남은 것

- **마커도 없고 앞에 문제 문장도 없는 격자**는 여전히 표로 잡힌다.
  좌표에도 내용에도 신호가 없으면 방법이 없다
- 보조 신호는 **값이 반복되는 짝짓기형 문제**에 맞춰져 있다.
  선택지가 전부 다른 긴 문장이면(그런 건 대개 한 열이라 표가 아니지만) 걸리지 않는다
- 지금은 본문 블록으로 되돌릴 뿐이다. 선택지를 `list` 같은 별도 종류로 표시하면
  문제-선택지 추출을 붙이기 쉬워진다 (스키마에 `kind` 하나 추가하면 된다)

## 배운 것 (2차)

**"내 이미지에서 됐다"는 해결이 아니다.** 1차 수정은 내 렌더에서 마커가
`① 무결성`으로 붙어 나왔기 때문에 통과했고, 마커가 검출되지 않는 제보자 환경은
검증하지 않았다. 제보 화면의 셀 내용(`① 없음`)을 처음부터 자세히 봤다면
바로 알 수 있었다.

**실패 조건을 인위적으로 만들어 재현하는 게 빠르다.** 마커를 흰색으로 덮는 것만으로
제보 상황을 그대로 만들 수 있었다.
